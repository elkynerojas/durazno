# Matriz de trazabilidad de las pruebas funcionales (HU-35)

Cada caso de prueba (`CP-<HU>-<n>`) corresponde a un criterio de aceptación de `BACKLOG.md`, en
el mismo orden. Mientras el SRS no esté aprobado (HU-01), los casos se trazan a esos criterios.
Cuando exista el SRS, se agregará la columna del requerimiento.

**Tipos de prueba:**

- `API`: pytest.
- `Web`: Vitest con Testing Library.
- `E2E`: Playwright con perfil de teléfono Android.
- `Manual`: paso a seguir a mano.
- `Doc`: revisión de un documento.

En la columna **Evidencia**, cada referencia apunta a una prueba como `archivo::nombre`. El
resultado de cada prueba en la última ejecución está en el informe
(`docs/pruebas/informe-pruebas-funcionales.md`).

**Cobertura:**

- **Completa:** las pruebas automatizadas demuestran el criterio.
- **Parcial:** una parte se verifica a mano, o depende de algo externo como un teléfono real, la
  impresora, el servidor desplegado o Icota.
- **Sin prueba:** el caso es solo manual.
